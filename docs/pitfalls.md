# Подводные камни

Что уже ломалось или легко ломается — и как это узнать по симптому. Формат: **симптом** → **причина** → **что сделано** → **как не наступить снова**. Сначала — по выпуску и обновлению (самое дорогое), потом — по коду.

## Выпуск и обновление

### «Повреждён (контрольная сумма не совпала)» при любом обновлении — заголовок `.gms` CorelDRAW 2026

**Симптом.** Плагин 1.0.x–1.1.1 при обновлении (на 1.1.1 и выше) отбраковывает скачанный файл: «Скачанный файл обновления не подошёл… контрольная сумма не совпала» (до 1.1.2 сообщение было общим — «повреждён»). Свежая установка из архива при этом работает.

**Причина.** CorelDRAW 2026 сохраняет `.gms` с заголовком: 18 байт, начинаются с `47 4D 53 01 0A` («GMS»), дальше — обычный файл OLE (`D0 CF 11 E0 A1 B1 1A E1`). Проверка «скачан настоящий файл плагина» (`IsOleFile` в `src/NeonUpdate.bas`) у 1.0.x–1.1.1 искала подпись OLE только в самом начале файла — и считала любой файл из CorelDRAW 2026 чужим. Контрольная сумма тут ни при чём, сообщение вводило в заблуждение.

**Что сделано (1.1.2, 12.11.2026).**
- `IsOleFile` понимает оба вида: подпись OLE в начале **или** после заголовка «GMS» на 18 байт; сообщение говорит настоящую причину (`upd_why_type` / `upd_why_sum` / `upd_why_nohash`) и пробует запасной адрес `gms_url2`.
- `tools/make_release.ps1` **снимает заголовок** перед выпуском: в релиз и в `dist/` идёт файл без заголовка. CorelDRAW 2026 такой файл загружает (проверено автором 12.11), а старая проверка 1.0.x–1.1.1 его пропускает — поэтому 1.1.2 и дальше приходят к старым версиям сами. Живое обновление 1.1.1 → 1.1.2 проверено автором 12.11.

**Как не наступить.**
- В релиз прикладывать **только** `release\NeonCenterline.gms` (его делает `make_release.ps1`), а не файл из `%APPDATA%\…\GMS` — там файл с заголовком, и его SHA-256 не совпадёт с `update.json`.
- Пока среди пользователей есть 1.0.x–1.1.1, снятие заголовка в `make_release.ps1` **не убирать**.
- Если новая версия CorelDRAW снова поменяет формат файла: проверить первые байты (`[IO.File]::ReadAllBytes($f)[0..31]` в PowerShell) и что CorelDRAW грузит файл без заголовка, прежде чем выпускать.

### Тег с буквой `v`, черновик, предварительный выпуск

**Симптом.** Плагины предлагают обновление, но скачивание — `HTTP 404`; значок скачиваний выпуска — ошибка.
**Причина.** `update.json` строит адреса из номера версии: `…/releases/download/<версия>/NeonCenterline.gms` и `…@<версия>/dist/…`. Тег `v1.2.0` вместо `1.2.0` — другой адрес. Черновик (Draft) не отдаёт файлы по прямой ссылке вообще.
**Как не наступить.** Тег = версия, без `v`, на `main`; публиковать (не Draft, не Pre-release). Проверка — [release.md](release.md#8-проверка-после-выпуска).

### Выпуск без файлов

**Симптом.** Значок скачиваний выпуска пишет ошибку (вида «repo or release not found»), ссылка на `.gms` из `update.json` — 404.
**Причина.** Выпуск опубликован, а файлы (Assets) не приложены (так было с 1.1.0 — пока автор не «залил файлы»).
**Как не наступить.** Перед публикацией — оба файла в Assets: `NeonCenterline.gms` и `NeonCenterline-<версия>.zip`. `update.json` пушить **после** проверки файлов. Значки shields.io кэшируются — после исправления могут показывать старое несколько минут.

### `update.json` запушен раньше выпуска

**Симптом.** Плагины в тот же день предлагают обновление и не могут скачать (`HTTP 404`), а ежедневная проверка в этот день больше не повторится.
**Причина.** Порядок выпуска нарушен: плагины читают `update.json` из `main` сразу.
**Как не наступить.** Порядок: `dist/` → выпуск с файлами → `update.json` ([release.md](release.md)). Если уже случилось — быстро опубликовать выпуск с файлами или откатить `update.json` коммитом.

### jsDelivr: тег кэшируется навсегда, `@main` — до ~12 часов

**Симптом.** Запасной адрес отдаёт старый файл (или старый `update.json`).
**Причина.** jsDelivr кэширует файлы по тегу как неизменные, а по ветке `@main` — на часы.
**Как не наступить.**
- `dist/NeonCenterline.gms` пушить **до** создания тега — тег должен встать на коммит с новой сборкой (иначе `gms_url2` вечно отдаёт старую сборку с другой контрольной суммой).
- Теги не переносить и не пересоздавать: jsDelivr уже мог запомнить содержимое. Ошибся со сборкой после тега — выпускать следующую версию (1.2.1), а не перевыпускать ту же.
- Старый `update.json` на `@main` — сбросить кэш: открыть `https://purge.jsdelivr.net/gh/ShiZa039/NeonCenterline@main/update.json`.

### GitHub недоступен у части пользователей

**Симптом.** «Не удалось проверить обновления: …» и подсказка про блокировку.
**Причина.** `raw.githubusercontent.com` (и иногда `github.com`) блокируются некоторыми провайдерами.
**Что сделано.** `update.json` читается по трём адресам по очереди (`NEON_UPDATE_URL`, `…URL2` — jsDelivr, `…URL3` — github.com/raw), файл — по двум (`gms_url`, `gms_url2` — jsDelivr). Запросы — WinHTTP с прокси из настроек Windows (5 с), при ручной проверке — ещё MSXML (как браузер), затем `curl.exe` (10 с). Ежедневная тихая проверка MSXML не трогает: у него нет таймаутов, и он мог бы надолго подвесить CorelDRAW. Поэтому ручная проверка иногда проходит там, где ежедневная молчит.

### Тестовая сборка для проверки обновления содержит старый код

**Симптом.** «Не работает» то, что уже исправлено (так было с люверсами 12.11: проверялось в файле 1.1.1, собранном для проверки обновления).
**Как не наступить.** Перед проверкой функции — «О программе»: версия должна быть та, что проверяется. Для проверки обновления ставить файл прошлого выпуска из его Assets, после проверки — вернуться на текущий.

## VBA

### `And` / `Or` не сокращённые — «Subscript out of range»

**Симптом.** Ошибка индекса в условии, которое «не должно» доходить до индекса (раскладка по габаритам в 1.1.0: `If method = 0 And NtRot(j) <> 0` — массив `NtRot` при раскладке по габаритам не размечен).
**Причина.** VBA вычисляет обе части `And` / `Or` всегда. LibreOffice на стенде этого не ловит.
**Как не наступить.** Условия с индексом или с объектом, который может быть `Nothing`, — вложенными `If`:
```vb
If method = 0 Then
    If NtRot(j) <> 0 Then ...
```

### Объявления уровня модуля после процедур — «Variable not defined» / «Expected …»

**Симптом.** VBA не компилирует модуль, LibreOffice компилирует.
**Причина.** В VBA все `Dim` / `Private` / `Const` уровня модуля — до первой процедуры (так ломалось с `NT_ROW`).
**Как не наступить.** Объявления разделов — в блоках `'@@…_DECL_BEGIN / _END` в начале модуля. `tools/shadow_check.py` это проверяет.

### Переменная с именем процедуры — «Expected array»

**Причина.** Локальная переменная или параметр с тем же именем, что вызываемая процедура (регистр не важен: `right` и `Right`), — VBA видит переменную и не может её «вызвать».
**Как не наступить.** `tools/shadow_check.py` (ловит и дубли Public-имён между модулями).

### `NeonLF` — не больше 8 подстановок, процедура — не больше 64 КБ

- `NeonLF(key, a0 … a7)` — подстановки `{0}`…`{7}`; девятая молча не подставится. `tools/call_check.py` сверяет число подстановок в строке с аргументами вызова и что ключ есть в `strings.py`.
- VBA не компилирует процедуру больше 64 КБ текста — поэтому `NeonLang.bas` разбит на функции по 40 строк, а большие процедуры — на части.

### Число аргументов

**Симптом.** «Wrong number of arguments» в VBA (LibreOffice часто молчит).
**Как не наступить.** `tools/call_check.py` — после каждого изменения сигнатуры.

### Члены, которых нет в старых CorelDRAW, — только через `Object`

`Shape.Properties`, `Document.Undo`, `Shape.UngroupEx`, `ActiveView.ToFitShapeRange` и т. п. вызываются через переменную `As Object` (`Set o = sh: o.Properties(...)`), с `On Error Resume Next`. При раннем связывании модуль в старом CorelDRAW не скомпилировался бы целиком — не работала бы ни одна кнопка.

### Ошибка посреди команды — CorelDRAW «замёрз», единицы сменились

**Симптом.** После ошибки экран не перерисовывается, линейки в миллиметрах, Ctrl+Z отменяет странно.
**Причина.** Команда включает `Optimization = True`, `EventsEnabled = False`, ставит `Unit = cdrMillimeter`, открывает `BeginCommandGroup`; ошибка выкинула её до восстановления.
**Как не наступить.** Шаблон каждой команды: `On Error GoTo Fail` → `Fail: errText = Err.Description: Resume Fin` → в `Fin:` вернуть всё (`EventsEnabled`, `Optimization`, `EndCommandGroup`, `Unit`) и только потом сообщение. См. `SimplifyContours` / `PlaceGrommets`.

### `Environ$("TEMP")` портит путь с русским именем пользователя

`Environ$` отдаёт ANSI — на нерусской Windows путь с кириллицей ломается. Временная папка — через `WScript.Shell.ExpandEnvironmentStrings` (`TempDir` в `NeonUpdate`), скрипт замены — в UTF-16.

## CorelDRAW

### Окно хода работы: модальное окно и работа из `Activate`

- Модальное окно (`Show`) останавливает код до закрытия — поэтому работа запускается **из** окна: `NeonJobRun` → `frmNeonRun` в режиме 5 → `UserForm_Activate` → `NeonJobGo` → та же команда, теперь с `NeonInJob(...) = True` (окно параметров второй раз не показывается). Без формы задание выполняется сразу.
- `DoEvents` — только в `NeonProgStep`, не чаще 5 раз в секунду: без него окно «Не отвечает», при каждом шаге — расчёт замедляется в разы.
- Крестик и Esc окно не закрывают (`QueryClose`): посреди расчёта документ трогать нельзя. Отмены расчёта нет.
- `NeonProgEnd` — **до** любого `MsgBox` (`NeonReport` зовёт его сам): иначе сообщение под окном хода работы.

### «Отмена» в отчёте отменила чужое действие

**Причина.** `NeonReport` по «Отмене» делает `ActiveDocument.Undo` — один шаг. Если команда ничего не поменяла (своей группы отмены нет), отменится предыдущее действие пользователя.
**Как не наступить.** `canUndo = True` — только когда что-то изменено и всё изменение — одна группа `BeginCommandGroup` / `EndCommandGroup`. Центральные линии — только «ОК»: там две группы (расчёт и подгонка под рез).

### Копирование отчёта в буфер обмена

Работало через раз — убрано в 1.1.1 (вместо него «ОК / Отмена»). Не возвращать.

### Контур «замкнут на глаз», а у Corel — нет

**Симптом.** Люверсы: «нет замкнутого контура (подпутей: N, замкнутых: 0; концы не сходятся)» на прямоугольнике, нарисованном линиями.
**Причина.** У подпути нет признака `Closed`, или контур собран из отдельных отрезков.
**Что сделано (1.1.2).** `GromChain` собирает куски, концы которых ближе `GROM_JOIN` = 0.5 мм, в замкнутые контуры (с обратным ходом, где нужно). Не прямоугольник и не кривая (эллипс, многоугольник…) — сначала `DisplayCurve`, не вышло — временная копия `ConvertToCurves` (`GromBest`).

### Люверсы на рисунке внутри баннера

**Причина.** Группа «баннер + рисунок» обходится насквозь — у каждого элемента свой край.
**Что сделано (1.1.2).** Объект, габарит которого внутри габарита другого выделенного объекта, пропускается (из одинаковых габаритов — первый).

### Метки своих объектов и язык интерфейса

Свои объекты плагин узнаёт по `Properties("NeonCenterline", 1)`: `same`, `sheet`, `frame`, `label`, `hem`, `grom`. Запасной путь (CorelDRAW без `Properties`, файлы первых сборок) — по началу имени, а имена **на языке интерфейса**: после смены языка по имени объекты прежнего языка не узнаются. Раскладка разбирает всегда только `same` и `sheet` (`NtUnpack`); группы люверсов — нет.

### Миллиметры в ядре «Моно» и мелкий текст

**Симптом.** На буквах 5–6 мм (гравировка) линии пропадают, отрезки торчат из букв, дуги ломаные; на 15 мм концы не доходят, острия не сходятся.
**Причина.** Почти все пороги ядра — в долях ширины штриха W (масштабируются с буквой), но три вещи — в миллиметрах: отступ конца D/2 (с фрезой 8 мм — 4 мм при штрихе 0,8 мм), допуск аппроксимации `P_TOL` = 0,25 мм и метка точки `P_DOT` = 0,5 мм. А `Retract`, когда отступ длиннее линии, уводил её конец за начало.
**Что сделано (1.1.3).** Линия, которую отступ съел целиком, пропускается (`Retract` → `np_ = 1`, счётчик `NeonMonoDropped`); отчёт предупреждает, если отступ больше штриха (`NeonMonoThinW`); допуск — не грубее W/16; метка точки — не больше четверти точки; острие — тот же отступ `EndOff()`, что и у концов. На размерах неона (штрих от 4 мм) результат прежний — весь тестовый шрифт до и после, узел в узел (`tools/stands/mono_font.py`).
**Как не наступить.** Новые пороги в ядре — в долях W; миллиметры — только с потолком по W. Любая правка «Моно» — `tools/stands/mono_font.py snap` до и после и `diff` (см. [development.md](development.md#моно-и-курсив)).

### Имя линий и имя панели — это идентификаторы

- «Неон: центр N» — по этому имени «Длина», «Выделить линии», подгонка под рез и люверсы (пропуск линий) узнают центральные линии, в том числе в старых файлах. Не переименовывать.
- «Неон (NeonCenterline)» — сброс и проверка панели (`ResetNeonBar`, `NeonBarProbe`) ищут панель по подстроке `NeonCenterline` в имени. Убрать её из имени — сломать обновление панели.

## Панель

### После обновления на панели старые кнопки

**Причина.** CorelDRAW вписывает кнопки дополнения в рабочее пространство один раз и новые в стоящую панель сам не добавляет; файл значков `Resources<N>.dll` занят работающим CorelDRAW и не перезаписывается.
**Что сделано.**
- Набор кнопок N: метка `[NeonToolbar N]` в `AppUI.xslt` = `NEON_TOOLBAR_VER` в `NeonUI.bas`; значки — **новым именем файла** `Resources<N>.dll` на каждый набор.
- Плагин сам видит старые файлы в Addons и один раз предлагает обновить (права администратора), после перезапуска сбрасывает **только** панель «Неон». Рабочее пространство может догрузиться после `GlobalMacroStorage_Start` и вернуть старые кнопки — поэтому проверка повторяется при открытии окна документа, до трёх попыток.
- Вручную — макрос `NeonCenterline.NeonUI.ResetToolbar` (с отчётом).
**Как не наступить.** Меняешь состав кнопок, подписи или значки — поднять `NEON_TOOLBAR_VER` **и** метку в `AppUI.xslt`, затем `build_resources.py` и `gen_addon.py` (он сверяет метку и имя DLL).

### Установка панели с правами администратора не срабатывала

Длинная команда через `cmd /c` при запуске с повышением прав не выполнялась. `InstallToolbar` пишет команды в `.cmd` рядом с временной папкой и с `runas` запускает его; ждёт файлы в Addons по журналу (`%TEMP%\NeonCenterline_addon.log`). Сбой — `.cmd` можно запустить вручную.

## Стенд LibreOffice

- **Ошибка компиляции = молчаливое зависание.** LibreOffice без экрана показывает окно ошибки, которого никто не видит. Всегда с таймаутом (`tools/lo_stand.py` и `tools/lo_compile.py` его ставят). Почти всегда — не хватает процедуры вне вырезанного раздела (`PutS`, `NormV`, `BzPt`) или объявлений (`*_DECL`); `lo_stand.module()` дописывает процедуры сам.
- **Заглушки окна хода работы.** Разделы `*GEO` зовут `NeonProgStep` / `NeonProgPack` / `NeonProgBox` / `NeonProgCompare` — на стенде нужны пустые (`lo_stand` добавляет).
- **Массивы.** В LibreOffice присваивание массива может не копировать его — оба имени смотрят в один массив. Расхождение только на стенде — проверить это первым делом.
- **Литералы больше ~64 КБ** LibreOffice не компилирует — отсюда сжатая запись строк в `NeonLang.bas`.
- **LibreOffice прощает** не сокращённые `And`/`Or`, объявления после процедур, лишние аргументы: зелёный стенд не заменяет `shadow_check` и `call_check`.

## Windows, PowerShell, кодировки

- **PowerShell 5.1 читает `.ps1` без BOM как ANSI.** В `install.ps1` и `make_release.ps1` не-ASCII — только в комментариях; всё, что печатается и сравнивается, — латиницей.
- **Импорт `.bas` в редактор VBA — в кодировке Windows.** `src/*.bas` — UTF-8: сборщик `NeonBuild` читает их сам и добавляет через `AddFromString`; сам `build/NeonBuild.bas` — только ASCII (его импортируют File → Import). Ручной импорт — через `tools/to_ansi.py` (папка `src_ansi/`).
- **Строки интерфейса в коде — только ASCII** (`NeonLang.bas`, запись `LD`): не зависят от кодовой страницы Windows и проходят через LibreOffice.
- **Концы строк.** `.gitattributes`: `*.bas`, `*.txt`, `*.cmd`, `*.ps1` — CRLF (VBA и `cmd` иначе спотыкаются). `.gms`, `.dll` — двоичные, git определяет сам.
- **`certutil` бывает запрещён политикой** — SHA-256 тогда через PowerShell `Get-FileHash`; нет обоих — «не удалось посчитать контрольную сумму».
- **Несколько версий CorelDRAW.** `install.ps1` берёт самую новую по версии `CorelDRW.exe`, а не по имени папки (старые версии оставляют папки).

## Репозиторий и процесс

- **Сгенерированные файлы не править руками:** `src/NeonLang.bas` ← `tools/strings.py`; `src/NeonMono.bas`, `src/NeonScript.bas` ← `core/*.bas`; `src/NeonAddon.bas` ← `addon/NeonCenterline/*`; `README.txt` ← `README.md`. Правка в сгенерированном файле пропадёт при следующем запуске генератора.
- **«Моно» заморожен:** меняется только при нулевой регрессии на `font/SABNeonTest.ttf`.
- **Геометрия — сначала прототип** (`proto/`), потом VBA один в один, потом стенд. Иначе расхождение не с чем сравнить.
- **На GitHub — только этот репозиторий.** Ничего другого не трогать без ведома автора.
