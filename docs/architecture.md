# Устройство плагина

Как плагин работает изнутри: от кнопки до объектов в документе, где хранятся настройки, как обновляются панель и сам плагин. Карта файлов и порядок работы — [development.md](development.md).

## Общая схема

```
Кнопка панели «Неон» (addon/NeonCenterline/AppUI.xslt)
  └─ макрос NeonCenterline.<Модуль>.<Команда>          (файл NeonCenterline.gms в папке GMS)
       ├─ окно параметров (frmNeonRun, режимы 0–4)       — только при первом входе
       ├─ NeonJobRun → окно хода работы (режим 5)
       │     └─ Activate → NeonJobGo → та же команда, NeonInJob = True
       │           ├─ выделение → массивы точек          (раздел команды: объекты Corel)
       │           ├─ расчёт                             (раздел …GEO: только массивы)
       │           └─ массивы → новые объекты            (одна группа отмены)
       └─ NeonReport: «ОК / Отмена»                      (Отмена = Ctrl+Z всего действия)
```

| Модуль | Команды (макросы для кнопок) |
|---|---|
| `NeonUI` | `RunMono`, `RunScript`, `ShowSettings`, `CheckUpdates`, `ShowAbout`, `ResetToolbar` |
| `NeonTools` | `SimplifyContours`, `CleanContours`, `SplitLetters`, `NestSheets`, `GroupSame`, `MakeNoodles`, `PlaceGrommets`, `MeasureLength`, `SelectNeonLines` |
| `NeonCut` | `FitToCut` |
| `NeonAddon` | `InstallToolbar` |
| `NeonUpdate` | (из `NeonUI`) `NeonUpdateCheck`, `NeonDailyUpdateCheck` |
| `NeonMono`, `NeonScript` | ядра центральных линий (`NeonMonoRun`, `NeonScriptRun`), без интерфейса |
| `NeonLang` | строки RU/EN: `NeonL(key)`, `NeonLF(key, a0…a7)`, `NeonLangCode()` |

## Жизнь команды

1. **Проверки:** есть документ, есть выделение — иначе сообщение и выход.
2. **Окно параметров** (`AskGrommetParams`, `AskNestParams`, `AskNoodleParams`, `AskSimplifyParams`, для центральных линий — окно режима 0): показывается, если команда вызвана не из окна хода работы (`Not NeonInJob("<задание>")`). «Отмена» — выход. Значения сохраняются в реестр, команда дальше читает их оттуда.
3. **Окно хода работы:** `NeonJobRun "<задание>", заголовок` открывает `frmNeonRun` в режиме 5 модально; его `UserForm_Activate` зовёт `NeonJobGo`, а тот по имени задания — ту же команду ещё раз. Задания: `mono`, `script`, `nest`, `split`, `simp`, `clean`, `same`, `len`, `sel`, `grom`, `noodle`, `cut`. Формы нет (ручная сборка без окон) — задание выполняется сразу.
4. **Работа:** единицы — миллиметры (`ActiveDocument.Unit`, потом вернуть), `BeginCommandGroup` (всё действие — один шаг отмены), `Optimization = True`, `EventsEnabled = False`. Ход: `NeonProgPhase текст, шагов` — новый этап; `NeonProgStep i` / `NeonProgTick` — шаг (окно обновляется не чаще 5 раз в секунду, тогда же `DoEvents`). Крестик и Esc окно не закрывают.
5. **Конец:** всё вернуть (в том числе при ошибке — `Fail: … Resume Fin`), `NeonProgEnd`, затем `NeonReport msg, заголовок, canUndo` («ОК / Отмена» при `canUndo`, иначе только «ОК») и `NeonToolbarCheck` (не пора ли обновить панель).

**Оставить оригинал** (раскладка, очистка, разбивка, упрощение): работа идёт с копиями (`Duplicate`), копия без изменений удаляется; раскладка копирует всё выделение (`ShapeRange.Duplicate`), не вставшие на лист копии удаляются. Текст переводится в кривые тоже в копии.

## Окна

| Окно | Режим | Что |
|---|---|---|
| `frmNeonRun` | 0 | центральные линии: фреза, отступ конца, тип неона, «Курсив — шрифт как образец», кратность реза и подгонка |
| | 1 | упрощение: допуск, «Оставить оригинал», «Показывать окно» |
| | 2 | люверсы: отступ, шаг, точка (диаметр, цвет), усиление углов, контур под подгиб, свой слой |
| | 3 | раскладка: лист (готовые и свои размеры), поля, зазор, способ, «матрёшкой», заполнение, по цветам, длина по раскладке, подписи, оригинал, группы |
| | 4 | лапша: длина, ширина, количество, хвосты, фреза |
| | 5 | окно хода работы (этап, полоса, «N из M», секунды) |
| `frmNeonSettings` | — | Настройки (окно создаёт сборщик, строки упрощения и «Оставлять оригинал» окно добавляет само) |

Окно параметров **само создаёт недостающие поля** при открытии (`frmNeonRun.code.txt`): форма из старой сборки не мешает новым галочкам. Раскладка элементов в коде — «вслепую», по координатам (`Top`); новые строки сдвигают следующие.

## Инструменты: что считает каждый раздел

Расчёт — в разделах `src/NeonTools.bas` `'@@ИМЯGEO_BEGIN` / `_END` (объявления — `'@@ИМЯ_DECL…`); разделы повторяют прототипы `proto/*.py` один в один (их docstring — подробное описание алгоритма).

| Инструмент | Раздел / файл | Прототип | Суть |
|---|---|---|---|
| Моно, Курсив | `core/*.bas` → `src/NeonMono.bas`, `src/NeonScript.bas` | `centerline.py`, `centerline2.py` | контуры → ресэмплинг → триангуляция Делоне → хордальная ось → обрезка «усиков» по локальной ширине штриха → слияние развилок → цепочки со сквозным проходом через развилки → сглаживание → концы на D/2 (или заданный отступ) от края → кривые Безье с минимумом узлов (допуск 0.25 мм). «Курсив» — то же плюс ход пера и «шрифт как образец» |
| Упростить | `SIMP` | `simplify.py` | углы (касательные > 10° и поворот хорд > 25°) остаются углами; участки между углами — в точки с шагом 4·допуск, фит кубиками Безье (Шнайдер) с допуском |
| Очистить | `CLEANGEO` | `cleanup.py` | заливка по ненулевой обмотке (как у текста в кривых); кривые режутся во всех пересечениях; кусок остаётся, если залита ровно одна сторона; лоскуты меньше 0.3 мм² или тоньше 0.15 мм уходят |
| Разбить на буквы | `LETTERSGEO` | `letters.py` | для каждого контура — сколько других его окружают: чётно — наружный, нечётно — дырка ближайшего; точки и акценты — к своей букве; острова в дырках — отдельно |
| Одинаковые | `SAMEGEO` | `nesting.py` (`shape`) | ключ цвета и габарит — предотбор; контуры сравниваются по точкам с шагом 0.5 мм с допуском 0.1 мм, без поворота и зеркала, независимо от узлов и начала обхода |
| Лапша | `NOODLEGEO` | `noodles.py` | N+1 горизонтальных резов зигзагом сверху вниз и 2 вертикальных отреза в конце; с фрезой — шаг ширина + D, отрезы на D/2 за концами |
| Раскладка по габаритам | `NESTGEO` | `nesting.py` | прямоугольники габаритов, MaxRects, без поворота; несколько порядков деталей — лучший |
| Раскладка по контуру | `NESTRASTER` | `rasternest.py` | деталь — клетки r×r, r = √(площадь листа / 10⁶) в пределах 0.5…5 мм; клетка занята, если центр внутри контура или ближе g/2 + 0.7072·r к нему (зазор соблюдается всегда); без «матрёшки» дырки деталей заполняются (заливка от края); место — первое свободное по строкам (или столбцам); открыты последние 3 листа; варианты — меньше листов, затем короче последний |
| Люверсы | `GROMGEO` | `grommets.py` | куски контура собираются в замкнутые (`GromChain`, концы ближе 0.5 мм); ломаная → смещение внутрь на отступ → люверс в каждом углу (излом > 30° или середина тугого скругления), между углами равномерно не реже шага; усиление углов; контур под подгиб (`GromHem`) — смещение наружу на выпуск, острые углы (не дальше 4·выпуска), ломаная с шагом 2 мм, точки на одной прямой убираются |
| Кратность реза | `NeonCut.bas` | — | кусок укорачивается до ближайшей меньшей кратной длины за счёт свободных концов (поровну или только с конца) |

## Объекты, которые создаёт плагин

| Что | Где | Имя | Метка `Properties("NeonCenterline", 1)` |
|---|---|---|---|
| Центральная линия | слой «Неон - центр», красная волосяная | «Неон: центр N» (не зависит от языка) | — (узнаётся по имени) |
| Группа одинаковых | слой объектов | «Одинаковые: N шт · Ш × В мм» | `same` |
| Лист раскладки (группа) | слой деталей | «Раскладка: лист i из n · …» | `sheet` |
| Рамка листа | в группе листа | «Раскладка: рамка листа i» | `frame` |
| Подпись листа | в группе листа | «Раскладка: подпись листа i» | `label` |
| Люверсы объекта (группа) / точка | слой баннера или «Люверсы» | «Люверсы: N» / «Люверс» | `grom` |
| Контур под подгиб | слой баннера | «Подгиб N мм» | `hem` |
| Лапша (группа) | центр страницы | «Лапша: N шт · Ш × Д мм» | — |

Метка — основной способ узнать свой объект (не зависит от языка); запасной — начало имени на текущем языке (CorelDRAW без `Properties`, файлы первых сборок). Раскладка разбирает всегда только `same` и `sheet`; рамки и подписи прежней раскладки из выделения убирает. Люверсы пропускают свои `grom` / `hem`, слой «Люверсы» и центральные линии.

## Строки и языки

- Все строки — в `tools/strings.py`: `ключ: ('русский', 'english')`, `{0}`…`{7}` — подстановки, `\n` — перенос.
- `tools/gen_lang.py` → `src/NeonLang.bas`: строки в коде **только ASCII** (сжатая запись: `#` переключает кириллицу, `$XXXX` — любой символ), функции по 40 строк — VBA не компилирует процедуру больше 64 КБ, LibreOffice — модуль с литералами больше ~64 КБ.
- Язык: `UI\Lang` (`ru` / `en`), пусто — по языку Windows. Новый язык — колонка в `strings.py` и ветка в `gen_lang.py`.

## Панель

- Файлы — `addon/NeonCenterline/`: `AppUI.xslt` (кнопки, списки, команды), `UserUI.xslt`, `Coreldrw.addon`, `config.xml` (связь GUID кнопки → подпись и значок), `Resources<N>.dll` (значки и подписи набора N). GUID кнопок постоянные: `uuid5('sabcore/neoncenterline/<ключ>')` в `build_resources.py`.
- Набор кнопок N: метка `[NeonToolbar N]` в `AppUI.xslt` = `NEON_TOOLBAR_VER` в `NeonUI.bas` (сейчас 12). `gen_addon.py` проверяет совпадение и кладёт все файлы панели внутрь плагина (`NeonAddon.bas`), чтобы `InstallToolbar` мог поставить их в любой CorelDRAW.
- `InstallToolbar`: файлы → `%TEMP%\NeonCenterline_addon\`, команды копирования → `.cmd`, запуск с `runas` (права администратора), копия в `Application.AddonPath\NeonCenterline`, старые `Resources*.dll` удаляются, если не заняты. Плагин ждёт файлы по журналу `%TEMP%\NeonCenterline_addon.log`.
- `NeonToolbarCheck` (при командах плагина, при запуске CorelDRAW и открытии окна — из `ThisMacroStorage`): `UI\ToolbarVer` = текущий набор — ничего; файлов панели в Addons нет — запомнить и не трогать; файлы старые — один раз предложить `InstallToolbar`; файлы этого набора — сбросить панель «Неон» (`CommandBar.Reset` у панели, в имени которой есть `NeonCenterline`) и проверить, что кнопки нового набора на месте (`NeonBarProbe`); три неудачи — оставить как есть.
- `ResetToolbar` — то же вручную, с отчётом.

## Обновление

**Где лежит:** `update.json` в `main`:
```json
{ "version": "1.1.2",
  "gms_url":  "https://github.com/ShiZa039/NeonCenterline/releases/download/1.1.2/NeonCenterline.gms",
  "gms_url2": "https://cdn.jsdelivr.net/gh/ShiZa039/NeonCenterline@1.1.2/dist/NeonCenterline.gms",
  "sha256":   "64 hex",
  "notes_ru": "…", "notes_en": "…" }
```

**Когда:** раз в сутки после расчёта центральных линий (`Update\Daily`, `Update\LastCheck`) — тихо (без сообщений «нет обновлений» и ошибок сети); по кнопке «Проверить обновления» — с сообщениями.

**Как (`NeonUpdate.bas`):**
1. Есть `Update\Pending` новее текущей версии и файл `PendingFile` на месте — скачано раньше, но не поставлено (выход из Windows убил скрипт): снова запустить скрипт замены, не скачивая.
2. `update.json` — по очереди `NEON_UPDATE_URL` (raw.githubusercontent.com), `NEON_UPDATE_URL2` (jsDelivr `@main`), `NEON_UPDATE_URL3` (github.com/…/raw), с меткой времени против кэша; первый ответивший. Каждый запрос: WinHTTP (таймаут 5 с, прокси из настроек Windows) → только при ручной проверке MSXML (как браузер, но без таймаутов) → `curl.exe` (10 с).
3. Версия не новее (`VerCmp`, по числам) — выход. Новее — вопрос с заметками `notes_ru` / `notes_en`.
4. Файл — `%TEMP%\NeonCenterline_<версия>.gms`, сначала с `gms_url`, не подошёл — с `gms_url2` (WinHTTP 60 с → `curl.exe` 120 с). Проверки: файл больше 1 КБ и **подпись OLE** в начале или после заголовка «GMS» на 18 байт (`IsOleFile`); **SHA-256** = `sha256` (`certutil`, нет — PowerShell `Get-FileHash`).
5. Скрипт замены `%TEMP%\NeonCenterline_update.vbs` (UTF-16, скрыто через `wscript`): ждёт, пока не останется процессов `CorelDRW.exe` (проверка раз в 2 с, до суток), копирует текущий `.gms` в `.gms.bak`, кладёт новый, удаляет скачанный файл и себя.
6. В реестр — `Pending` / `PendingFile`; сообщение «установится, когда вы закроете CorelDRAW».

Путь к текущему файлу — из `GMSManager.Projects` (проект, чей файл называется `NeonCenterline.gms`).

**Формат файла.** CorelDRAW 2026 пишет `.gms` с заголовком «GMS» (18 байт) перед OLE; `make_release.ps1` снимает его, чтобы файл принимали плагины 1.0.x–1.1.1 — [подробно](pitfalls.md#повреждён-контрольная-сумма-не-совпала-при-любом-обновлении--заголовок-gms-coreldraw-2026).

**После обновления** при первой команде — `NeonToolbarCheck`: если поменялся набор кнопок, предложить обновить панель.

## Установщик

`install.cmd` → `install.ps1`:
1. Ищет `CorelDRW.exe` в `Program Files\Corel` и берёт **самую новую по версии файла** (не по имени папки).
2. `NeonCenterline.gms` → `%APPDATA%\Corel\<папка версии>\Draw\GMS\` (папка с таким же именем, как у программы; нет — последняя использованная с `Draw\GMS`). Без прав администратора.
3. `addon\NeonCenterline` → `<папка программы>\Addons\NeonCenterline` — с правами администратора (повторный запуск себя с `-AddonOnly`); старые `Resources*.dll` других наборов удаляются.
